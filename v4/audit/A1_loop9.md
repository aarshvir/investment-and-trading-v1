## 3. Must-fix to reach >=95 (ranked by score impact)

1. **(criteria 1/4, highest impact, sixth consecutive loop, worse failure type) Add a pre-publication control aimed specifically at fabricated/hallucinated forward-looking numbers.** DA18 found, and I independently confirmed via WebFetch of the same primary source, that RMD.md's §5 stated a FY2027 guidance range ($5.75-$5.85B revenue, $12.00-$12.25 non-GAAP EPS) that simply does not exist anywhere in the 8-K it cited -- the release's only FY2027 guidance is a qualitative capital-return figure, and the same release discloses a material MatrixCare divestiture the dossier's bull case omitted. This is worse than Loops 5-8's mislabelled-but-real-number errors: it is an invented number attached to a real accession number, which neither `lead_dossier_precheck.py` (checks citation format/entity scope, not whether cited text contains the claimed number) nor `lead_xbrl_crosstie.py` (compares numeric XBRL tags, and prose guidance ranges have no tag) can catch by construction. **Fix:** require every forward-looking guidance claim to be stored with the verbatim quoted source sentence next to the number (not just an accession number), and add a check that flags any guidance-line dollar/EPS figure that cannot be found as a substring match (allowing for formatting) in the cited exhibit's extracted text -- this targets fabrication specifically, since arithmetic/entity/column checks cannot. Credit where due: the team's process caught this before release and executed the fix correctly (re-assess, downgrade, drop the name, restore CAH), which is why this scores 7-8, not lower.
2. **(carried, confirmed by design, seventh consecutive loop) The verification gate correctly reads OPEN** for exactly one reason: `outputs/c1_consistency.json` still narrates the pre-wave-6 build (holdings list and coverage counts) while the live frozen build is content 7ac48e4d... with a different 20-name list. I ran `code/lead_verify_gate.py` myself and confirmed no holding lacks an independent DA-series fact-check and no FAIL is left uncorrected -- the mechanism is doing what it is designed to do. Recommend actually completing one full cycle (fix -> re-run C1 last -> gate reads PASS) before the next release, since this exact gap has now been the sole open item in every loop from 3 through 9 and has never been observed to close on a build an outside auditor actually reviewed.
3. **(minor, criterion 10) Fix STATE.md's stale wave-6 log line.** It states "8 names in every ordering (was 14)" for the rule-(j) sensitivity result, but `outputs/lead_j_sensitivity.json`'s `in_every_ordering` array and FINAL_REPORT §6 both correctly show 9 names (ADP, CAH, CRH, EXC, GDDY, LVS, TJX, USB, VEEV).
