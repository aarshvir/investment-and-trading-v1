## 2. Must-fix to reach ≥95 (ranked by score impact)

1. **Dashboard audit-history table shows the wrong Loop-2 A3 score (criteria 1/9/10).** `dashboard/d4v.json` → `audits.loops[1]` ("loop": "2") has `"A3": 80.0, "avg": 85.7`; the correct values, per `audit/A3_loop2.json` (`"total": 89`) and FINAL_REPORT.md's own §10 table, are `A3: 89.0, avg: 88.7`. The wrong 80.0 is Loop 1's A3 score, apparently carried over by an indexing error. Fix: correct the dashboard generator (wherever it builds `audits.loops` — likely `code/lead_assemble.py` or `code/lead_report_sections.py`) to read Loop-2's own A3 file, republish the artifact, and add a check to C1/the guard script that diffs the dashboard's `audits.loops` array against the `audit/A*_loop*.json` files loop-by-loop (not just FINAL_REPORT.md's copy) so this class of error cannot recur silently.
2. **CRH and PGR (6.2% and 4.3% of the sleeve, both full conviction) have had no independent dossier fact-check since Loop 3 (criterion 4/10).** A.5 shows no DA row for either. I spot-checked CRH's Arcosa deal size myself this loop (passes), but neither has had a systematic multi-fact DA-style pass the way GM/LVS/RJF/HBAN/BR/DG/CMCSA/BKNG have. Fix: run a DA8 pass on CRH, PGR, MTB and ADP/DOV (formalizing what this audit and Loop 4's A2 did informally) before the next freeze.
3. **The structural risk that flagged GM's error (new full-conviction names entering the frozen build before any independent fact-check) is contained this loop only because no new full-conviction name was added — not because the process rule changed (criterion 4).** Wave-3 (189 queued names) is the next test. Fix: make explicit, written policy (in STATE.md, alongside rules a–j) that a name cannot move to full conviction (10% cap) in a frozen build without at least one completed independent fact-check pass, not just an auditor's informal spot check the same loop.
4. **RJF's §8 bull case 2 ("parent debt is under $1B") is not edited or footnoted after the correction retracts it (criterion 5/9).** A reader of §8 in isolation would not know this bull point no longer holds. Fix: strike or footnote bull-case point 2 in RJF.md §8 with a pointer to the Correction section, the same way the corrected figures are handled elsewhere.
5. **PAYX and other wave-2/wave-3 "eligible but not held" names close to the cutoff (e.g., PAYX at model rank 95, just outside the top 20 by rule (j)) are not covered by any sensitivity check analogous to `lead_j_sensitivity.json` for near-miss inclusion (criterion 6/7).** Minor: consider extending the (j) sensitivity file to report, for each of the 66 eligible-but-not-held names, how close it came under each ordering, so a reader can judge how fragile the boundary is.
