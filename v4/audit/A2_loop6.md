## 2. Must-fix to reach ≥95 (ranked by score impact)

1. **RJF's dossier §8 bull point 2 ("parent debt is under $1B") is still not struck or footnoted, five loops after its own Correction section said it "should be read as retracted" (criteria 4/5/9, carried over unresolved from Loop 5).** RJF is not a dead name: FINAL_REPORT §6 lists it, at full conviction, in "eligible but not held" — the first replacement if a held Financials holding's kill criterion fires. A reader who opens RJF.md and reads only §8 (the bull/bear summary, designed to be read standalone) still sees the retracted point presented as current. Fix: edit RJF.md §8 bull point 2 directly — strike it or add an inline footnote pointing to the Correction section — the one-line edit the Loop-5 must-fix already specified.
2. **No written rule (alongside a–l in STATE.md) requires a completed independent fact-check before a name enters the frozen build at full conviction (criterion 4, carried over from Loop 5).** This loop's six new full-conviction names did get DA9/DA10 passes before the 18:49:31 freeze, so the failure mode that produced the GM error has not recurred — but that is discipline, not a rule, and nothing stops the next wave from freezing before its DA pass exists. Fix: add an explicit rule to STATE.md (and ideally a check in `lead_build_portfolio.py` or `lead_verify_gate.py`) that blocks a name from reaching the 10%-cap tier without a recorded DA-series or auditor fact-check pass completed before the build timestamp.
3. **`lead_j_sensitivity.json` still does not report near-miss margins for the 96 eligible-but-not-held names (criteria 3/6/7, carried over from Loop 5).** PAYX and others are named in FINAL_REPORT §6/§13 as close calls but with no quantified distance to the cutoff under any ordering. Fix: extend `lead_j_sensitivity.py`'s output to report, for each not-held eligible name, its rank/score margin to the 20th name under each of the four orderings.
4. **The verification gate's blind spot for its own dashboard mirror (identified as fixed-once, Loop 5) has no committed regression test (criterion 10).** The specific instance is fixed, but nothing in C1 or the gate script currently asserts, on every future run, that `dashboard/d4v.json`'s `audits.loops` array matches `audit/A*_loop*.json` loop-by-loop — the same class of silent drift could recur with a different field. Fix: add that loop-by-loop diff as a named check inside C1 (`c1_consistency.py`), not just a one-off correction.
5. **DA9's MSCI retention-rate MINOR (Q4 2025 mislabeled "a year ago" when it is two quarters prior) is corrected in the dossier but the underlying kill-criterion comparator (currently citing the 93.4% two-quarters-ago figure rather than the true year-ago 94.4%) is not re-derived (criterion 4, minor).** The threshold (92%) and its distance-to-breach are unaffected either way, so this is low-impact, but the dossier's own kill-criterion text should cite the correct comparator, not just flag the labeling error. Fix: update MSCI.md §9 kill criterion 2 to cite Q2 2025's 94.4% as the year-ago figure.
